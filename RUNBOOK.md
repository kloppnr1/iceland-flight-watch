# Iceland Flight Watch

Public page: https://fly.strømsparer.dk (Hetzner server 89.167.101.11, Caddy, `/srv/flight-watch`).

## How data is updated
- **Cloud task (twice a day):** runs `fetch_gf.py cal` (Google Flights calendars via the open-source `fli` tool, `pip install flights click typer rich`), then `UPLOAD_TOKEN=... python3 upload.py cal`, which posts the calendars to `https://fly.xn--strmsparer-2cb.dk/api/cal` (always as a merge, so the server keeps files not sent). `fetch_gf.py` uploads by itself as it goes and stops after 90 minutes (`GF_MINUTES`), so a run fits the 2-hour limit. Calendar pass: new routes first, then the routes whose server calendar is oldest; uploads every 5 routes. Google rate-limits hard (20 calendars took about 30 minutes on 16 Nov), so with 5 destinations (50 routes, 100 calendars) one run refreshes part of the routes and the rest keep their earlier prices until the next run. With time left, the day-by-day pass (flight times, days the calendar missed) covers the next 120 days (`GF_DAY_DAYS`), routes with no or the oldest flight times first (`times_at` in the status), uploading each route when done. Days the calendar skipped are filled from the server's last day-by-day prices; a failed calendar search leaves the server's calendar as it was. Google blocks these requests from the Hetzner server (HTTP 429), so this part runs in the cloud.
- **Server (`/opt/flight-watch`):** `api.py` (systemd `flight-watch-api`, 127.0.0.1:8092, Caddy `/api/*`) stores uploads and watches. `run.sh` (systemd `flight-watch.service`, timer 4×/day and after each upload) runs `tp.py` (Travelpayouts) and `build.py` (Keflavík board, changes, watches) into `/srv/flight-watch/data`.
- **Destinations:** the page's airport picker ("to …") lists the destinations in `/opt/flight-watch/dests.json` (public copy `data/dests.json`, default Keflavík). "Airports and status…" on the page shows each destination's prices (Google or Travelpayouts, days, flight times, last update; `status` in latest.json) and adds one with the watch PIN (`POST /api/dests`). The API then runs `run.sh <CODE>`, which fetches Travelpayouts prices for that airport only and rebuilds, so first prices show within about a minute (marked as Travelpayouts on the page). `fetch_gf.py` reads the list from the site, does routes without Google prices first and uploads them right away (`{"merge": true}`), then the usual full run. Adding an airport also starts the cloud task "Flight watch – new airport" (`fetch_gf.py --new-only`, about 10 minutes) through its API trigger, with `GF_FIRE_URL` (`https://api.anthropic.com/v1/claude_code/routines/<trig_id>/fire`, not the claude.ai page address) and `GF_FIRE_TOKEN` in `.env`. The Delays tab always shows Keflavík flights (it reads Keflavík Airport's board); with another destination selected it says so.
- **Anywhere tab:** `anywhere.py` (cloud, needs `fli`) checks Google calendars between CPH, BLL, AAR, AAL, HAM, KEF and about 140 destinations worldwide plus every airport added on the page (read from `data/dests.json`, scanned first), both ways, for the next 6 months (about 5–6 hours) and, with `UPLOAD_TOKEN`, sends the day-by-day prices to `POST /api/anywhere` every 25 lookups (saved in `data/anywhere.json`). The page shows the cheapest one-way ticket per destination, or the cheapest round trip (two one-way tickets, home to the same airport) for a chosen number of days. Each card also says how the price compares with the route's usual price (the median of the coming 6 months), how many other days are within 10 % of it (one-way), and how soon it leaves. Sort by lowest price (default), best deal (savings in steps of 10 %, cheapest first within a step), leaving soonest (week by week, cheapest first within a week) or country; a max price can be set. The two airport lists work together: each Anywhere card has "Follow <city>" (opens "Airports and status…" with that airport filled in; PIN and Add airport as usual) or, for an airport already added, "All prices for <city>" (switches the page to it, Cheapest flights tab). The Anywhere "Fly to" picker lists the added airports first, and the add-airport search shows Anywhere's cheapest one-way price when the Anywhere data is loaded. Progress is kept in a local `.jsonl` file, so a stopped run continues (within 20 hours); `--upload-only` resends that file. Runs daily as the cloud task "Flight watch – anywhere".
- **Wrong PINs:** after 5 wrong PINs from one address in 15 minutes (or 40 in all in an hour) the API answers 429 until the time has passed; restarting `flight-watch-api` clears it.
- **Archive:** `data/runs/` gets a new file only when the Google prices differ from the last archived check.
- **Tests:** `python3 -m unittest discover tests` (API, watch maths, archive rule; no network needed).
- Secrets live in `/opt/flight-watch/.env` (TP_TOKEN, WATCH_PIN, UPLOAD_TOKEN), not in git.

## Deploy code changes
Push to `main`. The server pulls the repo every 5 minutes (`flight-watch-deploy.timer` → `/opt/flight-watch/autodeploy.sh`, read-only GitHub deploy key `/root/.ssh/flight_watch_deploy`) and installs changed scripts and the page by itself. New systemd units or Caddy changes still need SSH (`flight-watch.caddy` now has `encode zstd gzip`: copy it to the server's Caddy config and `systemctl reload caddy`) (deploy key in `Downloads\sport-tv-deploy` on Martin's PC).

## Open items (16 Nov 2026)
- **Upload token:** replaced 16 Nov. The token is a network secret for `fly.stromsparer.dk` (header `X-Upload-Token`) in the Default cloud environment, and the tasks run with the placeholder `UPLOAD_TOKEN=proxy-injected`. The tasks must run in the Default environment: the secret is not added in the Cowork environment, so uploads from there are refused (403). The scheduled tasks are therefore "Iceland flight watch – Google prices (Default)" and "Flight watch – anywhere (Default)"; the two older tasks without "(Default)" are switched off. To change it: new `UPLOAD_TOKEN` in `/opt/flight-watch/.env` + `systemctl restart flight-watch-api`, and the same value in the network secret.
- **Compression:** copy `flight-watch.caddy` to the server's Caddy config and `systemctl reload caddy`.
- **`flight-watch.service`** is only on the server; copy it into the repo.
- **Old archive files** in `data/runs/` from before the "only new prices" rule were left as they are.
